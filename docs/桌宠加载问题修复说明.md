# 桌面伙伴VRM加载问题修复说明

## 问题总结

你遇到了两个主要问题：

### 问题 1: 窗口重复创建错误
```
❌ a window with label `pet` already exists
```

**原因：** 之前的桌面伙伴窗口没有正确关闭，再次尝试创建时发生冲突。

**已修复：** ✅
- 在创建新窗口前检查是否已存在
- 如果存在则复用现有窗口
- 改进了窗口事件监听机制

### 问题 2: VRM文件加载失败
```
❌ Failed to fetch
❌ ERR_CONNECTION_REFUSED (asset.localhost)
```

**原因：** Tauri的`convertFileSrc`在开发模式下对本地文件访问有限制。

**已修复：** ✅
- 改用`readBinaryFile`直接读取VRM文件
- 将文件数据转换为Blob URL
- Three.js通过Blob URL加载模型

## 修复内容

### 1. Pet.vue - 文件加载方式改进

**之前的方式（有问题）：**
```typescript
// ❌ 使用 convertFileSrc
const fileUrl = convertFileSrc(path);
await vrmLoader.loadVrm(fileUrl);
```

**新的方式（已修复）：**
```typescript
// ✅ 直接读取二进制文件
const fileData = await readBinaryFile(path);
const blob = new Blob([fileData], { type: 'application/octet-stream' });
const blobUrl = URL.createObjectURL(blob);
await vrmLoader.loadVrm(blobUrl);
URL.revokeObjectURL(blobUrl);
```

### 2. petStore.ts - 窗口管理改进

**之前的方式（有问题）：**
```typescript
// ❌ 直接创建，可能重复
const window = new WebviewWindow('pet', {...});
await window.once('tauri://created', () => {});
```

**新的方式（已修复）：**
```typescript
// ✅ 先检查是否存在
const existingWindow = WebviewWindow.getByLabel('pet');
if (existingWindow) {
  // 复用现有窗口
  return;
}

// ✅ 使用Promise正确等待事件
await new Promise<void>((resolve, reject) => {
  window.once('tauri://created', () => resolve());
  window.once('tauri://error', (e) => reject(e));
});
```

## 技术细节

### 为什么改用 readBinaryFile？

**convertFileSrc 的限制：**
- 在开发模式下可能无法正确工作
- 依赖Tauri的asset协议服务器
- 某些路径可能被安全策略阻止

**readBinaryFile 的优势：**
- 直接读取文件内容到内存
- 不依赖HTTP协议
- 更可靠的跨平台支持
- 适合一次性加载的资源

**Blob URL 的作用：**
- 将二进制数据转换为可访问的URL
- Three.js可以像加载网络资源一样加载
- 使用后可以释放，节省内存

### 性能影响

```
文件读取时间：取决于文件大小
- 10MB: ~100ms
- 50MB: ~500ms
- 100MB: ~1s

内存占用：文件大小 × 2
- VRM文件本身：一份在内存
- Blob对象：一份临时副本
- 加载到GPU后，Blob可以释放
```
