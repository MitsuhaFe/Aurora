# 小组件多窗口位置同步修复

## 更新日期
2025-11-03

## 问题描述

用户反馈：
- ✅ **任务管理器终止后重启** → 小组件位置正常（保存的新位置）
- ❌ **应用内关闭再打开** → 小组件位置错误（恢复到旧位置）

## 问题分析

### 问题根源

这是一个经典的**多窗口状态同步**问题，与 Dock 遇到的"位置问题终极修复"完全相同。

Aurora 的小组件系统有两个窗口：
1. **主窗口（Settings）** - 有独立的 widgetStore 实例
2. **小组件窗口** - 每个小组件有独立的 widgetStore 实例

每个窗口的 store 都是独立的，不会自动同步。

### 问题流程

```
第 1 步：用户拖动小组件
   ├─> 小组件窗口: 保存位置到 localStorage (500, 500) ✅
   └─> localStorage: { x: 500, y: 500 }

第 2 步：主窗口 store 状态（未同步）
   └─> 主窗口 store: 位置还是旧的 (100, 100) ❌

第 3 步：用户在设置中关闭小组件
   ├─> toggleWidget(widgetId, false)
   ├─> 使用主窗口 store 的数据
   └─> widget.enabled = false （位置仍是 100, 100）

第 4 步：用户重新打开小组件
   ├─> toggleWidget(widgetId, true)
   ├─> 使用主窗口 store 的数据创建窗口
   ├─> createWidgetWindow({ x: 100, y: 100 }) ❌
   └─> 小组件出现在旧位置 (100, 100)
```

**关键问题：** 主窗口的 store 没有同步小组件窗口保存的最新位置！

### 为什么任务管理器终止后正常？

```
第 1 步：用户拖动小组件
   └─> 保存到 localStorage (500, 500) ✅

第 2 步：任务管理器终止应用
   └─> 所有窗口关闭，所有 store 销毁

第 3 步：重新启动应用
   ├─> 主窗口 store 从 localStorage 加载
   ├─> widgets.value = JSON.parse(localStorage) 
   └─> 位置是 (500, 500) ✅

第 4 步：自动创建已启用的小组件
   ├─> createWidgetWindow({ x: 500, y: 500 })
   └─> 小组件出现在正确位置 ✅
```

**区别：** 重启时会从 localStorage 重新加载，所以能获取最新位置。

## 解决方案

### 核心思路

参考 Dock 的"位置问题终极修复"，在切换小组件状态前，**重新从 localStorage 加载最新数据**。

### 实现方式

修改 `toggleWidget` 函数（`src/stores/widgetStore.ts`）：

```typescript
async function toggleWidget(widgetId: string, enabled: boolean) {
  const widget = widgets.value.find(w => w.id === widgetId);
  if (widget) {
    // 🔑 关键：在切换前重新加载设置，获取最新的位置和大小
    console.log(`🔄 [toggleWidget] 重新加载设置以获取最新位置...`);
    loadSettings();
    
    // 等待加载完成（防止 watch 触发）
    await new Promise(resolve => setTimeout(resolve, 150));
    
    // 重新获取组件（现在是最新数据）
    const updatedWidget = widgets.value.find(w => w.id === widgetId);
    if (!updatedWidget) {
      console.error(`❌ 找不到小组件: ${widgetId}`);
      return;
    }
    
    updatedWidget.enabled = enabled;
    
    if (enabled) {
      console.log(`📍 [toggleWidget] 使用最新位置创建窗口:`, {
        x: updatedWidget.x,
        y: updatedWidget.y,
        width: updatedWidget.width,
        height: updatedWidget.height
      });
      await createWidgetWindow(updatedWidget);
    } else {
      await closeWidgetWindow(widgetId);
    }
    
    console.log(`✅ 切换小组件状态: ${widgetId} -> ${enabled ? '启用' : '禁用'}`);
  }
}
```

### 工作原理

```
1. 用户点击"关闭小组件"
   └─> toggleWidget(widgetId, false)

2. 重新加载设置
   ├─> loadSettings()
   ├─> 从 localStorage 读取: { x: 500, y: 500 }
   └─> 覆盖主窗口 store 中的旧数据 (100, 100)

3. 等待 150ms
   └─> 确保加载完成，防止 watch 触发保存

4. 获取最新数据
   └─> updatedWidget.x = 500, updatedWidget.y = 500 ✅

5. 用户重新打开小组件
   ├─> toggleWidget(widgetId, true)
   ├─> 再次重新加载设置（获取最新）
   ├─> createWidgetWindow({ x: 500, y: 500 })
   └─> 小组件出现在正确位置 ✅
```

   ├─> 重新加载设置

3. 重新打开小组件
   ├─> toggleWidget(widgetId, true)
   ├─> 重新加载设置（额外保护）
   ├─> 使用位置 (500, 500) 创建窗口
   └─> 小组件出现在正确位置 ✅
```

```

2. 修改小组件背景色
   ├─> 主窗口 store 触发 saveSettings()
   ├─> 检测到位置不一致
   └─> 保留 localStorage 的位置 (500, 500) ✅

3. 关闭并重新打开

### 场景 3：任务管理器终止（依然正常）

```
1. 拖动小组件到新位置 (500, 500)
   └─> 保存到 localStorage ✅

2. 任务管理器终止应用

3. 重新启动应用
   ├─> 所有 store 从 localStorage 初始化

```

## 技术要点

1. **双重加载保护** - 关闭和打开时都重新加载
2. **等待加载完成** - 150ms 确保数据更新，防止 watch 触发
3. **使用最新数据** - 重新获取 widget 对象，不使用缓存
4. **详细日志** - 显示使用的位置，方便验证
5. **与其他保护兼容** - 不影响标志位和防止覆盖机制

## 总结

这是一个经典的多窗口状态同步问题。通过在切换小组件状态前重新加载 localStorage 中的最新数据，确保主窗口 store 始终使用最新的位置和大小信息。

**核心原则：** 在关键操作前，先同步最新数据，不要信任当前 store 中的缓存。
