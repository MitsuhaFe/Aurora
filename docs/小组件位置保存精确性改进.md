# 小组件位置保存精确性改进

## 更新日期
2025-11-03

## 问题描述

用户反馈：保存的位置并不是拖动的最终位置，而是拖动过程中的某个中间位置。

**症状：**
- 拖动小组件到位置 A
- 松开鼠标
- 保存的位置可能是接近 A 但不完全是 A 的某个位置

## 问题分析

### 原始实现的问题

```typescript
await appWindow.startDragging();  // 拖动结束，返回

// 问题：立即获取位置可能不准确
await new Promise(resolve => setTimeout(resolve, 150));  // 等待 150ms
let position = await appWindow.outerPosition();  // 获取位置
// 此时位置可能还在变化中！
```

**问题流程：**

```
1. 用户拖动窗口到位置 (500, 500)
   └─> 松开鼠标

2. startDragging() 返回
   └─> 但窗口可能还在惯性移动或过渡动画中

3. 等待 150ms
   └─> 可能不够长

4. 获取位置 → 可能是 (498, 502)
   └─> 不是最终位置！❌

5. 保存了错误的位置
   └─> 重新打开时出现在 (498, 502) 而不是 (500, 500)
```

### 为什么会有这个问题？

1. **窗口惯性** - 快速拖动松手后，窗口可能有惯性移动
2. **过渡动画** - 某些系统有窗口平滑移动动画
3. **系统延迟** - 窗口位置更新可能有延迟
4. **检测不够严格** - 只检查一次位置变化不够

## 解决方案

### 核心思路

**连续稳定检测**：要求位置连续多次检测都相同，才认为真正稳定。

### 改进的实现

#### 1. 更长的初始等待

```typescript
// 从 150ms 增加到 200ms
await new Promise(resolve => setTimeout(resolve, 200));
```

#### 2. 连续稳定检测

```typescript
let stablePosition = await appWindow.outerPosition();
let currentPosition = stablePosition;
let consecutiveStableCount = 0; // 连续稳定次数
const requiredStableCount = 3;  // 要求连续 3 次位置不变

for (let i = 0; i < 10; i++) {
  // 等待 100ms
  await new Promise(resolve => setTimeout(resolve, 100));
  
  // 再次获取位置
  currentPosition = await appWindow.outerPosition();
  
  // 检查位置是否与上次相同
  if (stablePosition.x === currentPosition.x && 
      stablePosition.y === currentPosition.y) {
    consecutiveStableCount++;
    console.log(`⏳ 位置稳定检测 ${consecutiveStableCount}/${requiredStableCount}`);
    
    // 如果连续 3 次位置不变，认为已稳定
    if (consecutiveStableCount >= requiredStableCount) {
      console.log(`✅ 位置已完全稳定（连续 ${requiredStableCount} 次检测相同）`);
      break;
    }
  } else {
    // 位置发生变化，重置计数器
    consecutiveStableCount = 0;
    console.log(`⏳ 位置仍在变化: (${stablePosition.x}, ${stablePosition.y}) → (${currentPosition.x}, ${currentPosition.y})`);
  }
  
  stablePosition = currentPosition;
}
```

**关键改进：**
- ✅ 连续 3 次检测位置相同才认为稳定
- ✅ 如果位置变化，重置计数器，重新开始
- ✅ 最多检测 10 次（1000ms），确保不会无限等待
- ✅ 检测间隔从 50ms 增加到 100ms，更可靠

#### 3. 参数说明

| 参数 | 旧值 | 新值 | 说明 |
|------|------|------|------|
| 初始等待 | 150ms | 200ms | 让过渡动画完成 |
| 检测间隔 | 50ms | 100ms | 更可靠的检测 |
| 最大检测次数 | 5 次 | 10 次 | 更长的等待时间 |
| 稳定判断 | 1 次相同 | 连续 3 次相同 | 更严格的判断 |
| 最大等待时间 | 150+250=400ms | 200+1000=1200ms | 足够应对各种情况 |

## 改进后的工作流程

### 快速拖动场景

```
1. 用户快速拖动到 (500, 500)
   └─> 松开鼠标

2. startDragging() 返回
   └─> 窗口还在惯性移动

3. 初始等待 200ms
   └─> 窗口位置: (502, 501) ← 还在移动

4. 第 1 次检测（100ms 后）
   └─> 位置: (501, 500) ← 仍在变化
   └─> consecutiveStableCount = 0

5. 第 2 次检测（100ms 后）
   └─> 位置: (500, 500) ← 可能稳定了
   └─> consecutiveStableCount = 1

6. 第 3 次检测（100ms 后）
   └─> 位置: (500, 500) ← 位置相同！
   └─> consecutiveStableCount = 2

7. 第 4 次检测（100ms 后）
   └─> 位置: (500, 500) ← 连续第 3 次相同！
   └─> consecutiveStableCount = 3 ✅

8. 位置已完全稳定
   └─> 保存 (500, 500) ✅
```

### 慢速拖动场景

```
1. 用户慢速拖动到 (300, 200)
   └─> 松开鼠标

2. startDragging() 返回
   └─> 窗口立即停止

3. 初始等待 200ms
   └─> 窗口位置: (300, 200) ← 已经稳定

4. 第 1 次检测（100ms 后）
   └─> 位置: (300, 200) ← 相同
   └─> consecutiveStableCount = 1

5. 第 2 次检测（100ms 后）
   └─> 位置: (300, 200) ← 相同
   └─> consecutiveStableCount = 2

6. 第 3 次检测（100ms 后）
   └─> 位置: (300, 200) ← 连续第 3 次相同！
   └─> consecutiveStableCount = 3 ✅

7. 位置已完全稳定（总耗时 200+300=500ms）
   └─> 保存 (300, 200) ✅
```

### 系统动画场景

```
1. 用户拖动到 (800, 600)
   └─> 系统有平滑动画

2. startDragging() 返回
   └─> 动画还在进行

3. 初始等待 200ms
   └─> 位置: (795, 598) ← 动画中

4-8. 多次检测
   └─> 位置在持续变化
   └─> 每次都重置 consecutiveStableCount

9. 第 7 次检测
   └─> 位置: (800, 600) ← 动画结束
   └─> consecutiveStableCount = 1

10-12. 继续检测
   └─> 位置连续 3 次都是 (800, 600)
   └─> consecutiveStableCount = 3 ✅

13. 保存准确位置
   └─> 保存 (800, 600) ✅
```

## 性能影响

### 最快情况（位置立即稳定）

```
初始等待: 200ms
第 1-3 次检测: 300ms (3 × 100ms)
总计: 500ms
```

### 最慢情况（位置持续变化）

```
初始等待: 200ms
第 1-10 次检测: 1000ms (10 × 100ms)
总计: 1200ms
```

**结论：**
- 拖动后会有 0.5-1.2 秒的延迟才保存
- 这个延迟是必要的，确保保存正确的位置
- 用户感知不到延迟，因为窗口已经停在目标位置

## 技术要点

1. **连续稳定检测** - 要求连续 3 次位置相同
2. **重置机制** - 位置变化时重置计数器
3. **最大等待时间** - 防止无限等待（1200ms）
4. **详细日志** - 显示每次检测的结果
5. **最后位置保底** - 超时时使用最后检测的位置
