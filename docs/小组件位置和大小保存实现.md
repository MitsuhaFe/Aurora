## 核心实现

### 1. DPI 缩放处理

#### 问题描述
在 Windows 系统上启用 DPI 缩放（如 125%、150%）时，存在两种坐标系统：
- **物理坐标** - 实际的屏幕像素坐标
- **逻辑坐标** - 独立于 DPI 的坐标

如果保存物理坐标但创建窗口时使用逻辑坐标，会导致位置偏移。

#### 解决方案

**保存位置时**（`src/views/Widgets/Index.vue`）：

```typescript
// 获取物理坐标
const finalPhysicalPosition = await appWindow.outerPosition();
// 获取 DPI 缩放因子（如 1.25）
const scaleFactor = await appWindow.scaleFactor();

// 转换为逻辑坐标
const logicalX = Math.round(finalPhysicalPosition.x / scaleFactor);
const logicalY = Math.round(finalPhysicalPosition.y / scaleFactor);

// 保存逻辑坐标
widgetStore.saveWidgetPosition(widgetId, logicalX, logicalY);
```

**创建窗口时**（`src/stores/widgetStore.ts`）：

```typescript
// 直接使用保存的逻辑坐标
const window = new WebviewWindow(`widget-${widget.id}`, {
  x: widget.x,  // 逻辑坐标，Tauri 会自动转换为物理坐标
  y: widget.y,
  width: widget.width,  // 逻辑尺寸
  height: widget.height,
  // ...
});
```

**调整大小时**（`src/views/Widgets/Index.vue`）：

```typescript
// 获取物理尺寸
const physicalSize = await appWindow.outerSize();
const scaleFactor = await appWindow.scaleFactor();

// 转换为逻辑尺寸
const logicalWidth = Math.round(physicalSize.width / scaleFactor);
const logicalHeight = Math.round(physicalSize.height / scaleFactor);

// 保存逻辑尺寸
widgetStore.saveWidgetSize(widgetId, logicalWidth, logicalHeight);
```

### 2. 位置稳定性检测

#### 问题描述
拖动结束后，窗口可能还在过渡动画中，过早获取位置会得到中间状态。

#### 解决方案

参考 Dock 的实现，使用多次检查确保位置稳定：

```typescript
// 1. 初始等待 150ms，让窗口过渡动画完成
await new Promise(resolve => setTimeout(resolve, 150));

// 2. 多次检查位置稳定性
let stablePosition = await appWindow.outerPosition();
await new Promise(resolve => setTimeout(resolve, 50));
let currentPosition = await appWindow.outerPosition();

let retries = 0;
while (
  (stablePosition.x !== currentPosition.x || stablePosition.y !== currentPosition.y) && 
  retries < 5
) {
  console.log(`⏳ 位置仍在变化，继续等待...`);
  await new Promise(resolve => setTimeout(resolve, 50));
  stablePosition = currentPosition;
  currentPosition = await appWindow.outerPosition();
  retries++;
}

console.log(`✅ 位置已稳定，开始保存...`);
```

**参数说明**：
- **初始等待**: 150ms - 大多数窗口过渡动画 < 150ms
- **检查间隔**: 50ms - 足够检测位置变化
- **最大重试**: 5 次 - 总共最多等待 450ms

### 3. 防止数据覆盖

#### 问题描述
多窗口环境下，主窗口修改设置可能会覆盖小组件窗口保存的位置和大小。

#### 解决方案

使用标志位区分不同的保存场景：

**标志位定义**（`src/stores/widgetStore.ts`）：

```typescript
// 标志：是否正在保存位置
const isSavingPositionMap = new Map<string, boolean>();

// 标志：是否正在保存大小
const isSavingSizeMap = new Map<string, boolean>();
```

**保存位置时设置标志**：

```typescript
function saveWidgetPosition(widgetId: string, x: number, y: number) {
  const widget = widgets.value.find(w => w.id === widgetId);
  if (widget) {
    // 🔑 设置标志，表示正在保存位置
    isSavingPositionMap.set(widgetId, true);
    
    try {
      widget.x = x;
      widget.y = y;
      saveSettings(); // 此时 saveSettings 知道是位置更新
    } finally {
      isSavingPositionMap.set(widgetId, false); // 保存完成后重置
    }
  }
}
```

**智能保存设置**：

```typescript
function saveSettings() {
  const stored = localStorage.getItem(STORAGE_KEY);
  let dataToSave = [...widgets.value];
  
  if (stored) {
    const storedWidgets = JSON.parse(stored);
    
    dataToSave = dataToSave.map(widget => {
      const storedWidget = storedWidgets.find(w => w.id === widget.id);
      if (!storedWidget) return widget;
      
      const isSavingPosition = isSavingPositionMap.get(widget.id);
      const isSavingSize = isSavingSizeMap.get(widget.id);
      
      let updatedWidget = { ...widget };
      
      // 如果不是正在保存位置，保留 localStorage 的位置
      if (!isSavingPosition) {
        const positionChanged = 
          widget.x !== storedWidget.x || 
          widget.y !== storedWidget.y;
        
        if (positionChanged) {
          console.log(`⚠️ 小组件 ${widget.id} 位置数据不一致，保留 localStorage 中的位置`);
          updatedWidget.x = storedWidget.x;
          updatedWidget.y = storedWidget.y;
        }
      }
      
      // 如果不是正在保存大小，保留 localStorage 的大小
      if (!isSavingSize) {
        const sizeChanged = 
          widget.width !== storedWidget.width || 
          widget.height !== storedWidget.height;
        
        if (sizeChanged) {
          console.log(`⚠️ 小组件 ${widget.id} 大小数据不一致，保留 localStorage 中的大小`);
          updatedWidget.width = storedWidget.width;
          updatedWidget.height = storedWidget.height;
        }
      }
      
      return updatedWidget;
    });
  }
  
  localStorage.setItem(STORAGE_KEY, JSON.stringify(dataToSave));
}
```

### 4. 防抖优化

#### 问题描述
窗口大小调整时会触发多次 ResizeObserver 回调，频繁保存影响性能。

#### 解决方案

使用防抖机制，300ms 内只保存一次：

```typescript
let resizeDebounceTimer: number | null = null;

async function debounceSaveSize() {
  if (!widgetId) return;
  
  if (resizeDebounceTimer) {
    clearTimeout(resizeDebounceTimer);
  }
  
  resizeDebounceTimer = window.setTimeout(async () => {
    // 获取并转换尺寸
    const physicalSize = await appWindow.outerSize();
    const scaleFactor = await appWindow.scaleFactor();
    const logicalWidth = Math.round(physicalSize.width / scaleFactor);
    const logicalHeight = Math.round(physicalSize.height / scaleFactor);
    
    // 保存
    widgetStore.saveWidgetSize(widgetId, logicalWidth, logicalHeight);
  }, 300); // 300ms 防抖
}
```

### 5. 配置加载保护

#### 问题描述
watch 监听器在加载设置时也会触发，可能导致刚加载的数据被覆盖。

#### 解决方案

使用加载标志防止重复保存：

```typescript
let isLoadingSettings = false;

function loadSettings() {
  isLoadingSettings = true;
  
  try {
    const stored = localStorage.getItem(STORAGE_KEY);
    if (stored) {
      widgets.value = JSON.parse(stored);
    }
  } finally {
    setTimeout(() => {
      isLoadingSettings = false;
    }, 100);
  }
}

watch(widgets, () => {
  if (isLoadingSettings) {
    console.log('⏭️ 正在加载设置，跳过自动保存');
    return;
  }
  saveSettings();
}, { deep: true });
```

## 完整工作流程

### 拖动小组件流程

```
1. 用户开始拖动小组件
   ├─> 记录拖动前的逻辑位置
   └─> 调用 startDragging()（阻塞）

2. 用户松开鼠标，拖动结束

3. 等待 150ms 让位置初步稳定

4. 多次检查位置稳定性
   ├─> 获取位置，等待 50ms
   ├─> 再次获取位置
   └─> 如果不同，继续等待

5. 位置稳定后
   ├─> 获取物理坐标
   ├─> 获取 DPI 缩放因子
   └─> 转换为逻辑坐标

6. 计算拖动距离
   └─> 如果 > 2px，保存位置

7. 保存位置
   ├─> 设置 isSavingPosition = true
   ├─> 更新 widget.x 和 widget.y
   ├─> 调用 saveSettings()
   └─> 重置 isSavingPosition = false
```

### 调整大小流程

```
1. 用户调整窗口大小
   └─> ResizeObserver 触发

2. 防抖处理
   └─> 300ms 内多次调整只触发一次

3. 获取尺寸
   ├─> 获取物理尺寸
   ├─> 获取 DPI 缩放因子
   └─> 转换为逻辑尺寸

4. 保存大小
   ├─> 设置 isSavingSize = true
   ├─> 更新 widget.width 和 widget.height
   ├─> 调用 saveSettings()
   └─> 重置 isSavingSize = false
```

### 主窗口修改其他设置流程

```
1. 用户在设置页面修改小组件配置（如颜色、透明度）

2. watch 触发 → saveSettings()

3. saveSettings() 检查标志
   ├─> isSavingPosition = false
   └─> isSavingSize = false

4. 对比 localStorage 中的数据
   ├─> 位置不一致？保留 localStorage 的位置 ✅
   └─> 大小不一致？保留 localStorage 的大小 ✅

5. 只更新其他配置，位置和大小保持不变 ✅
```

## 多窗口同步问题修复（2025-11-03 更新）

### 问题：关闭再打开位置恢复旧值

用户发现：
- ✅ 任务管理器终止后重启 → 位置正常
- ❌ 应用内关闭再打开 → 位置恢复到旧值

**原因：** 主窗口 store 没有同步小组件窗口保存的最新位置。

**解决方案：** 在 `toggleWidget` 中重新加载设置

```typescript
async function toggleWidget(widgetId: string, enabled: boolean) {
  // 🔑 关键：重新加载设置，获取最新的位置和大小
  loadSettings();
  await new Promise(resolve => setTimeout(resolve, 150));
  
  // 重新获取组件（现在是最新数据）
  const updatedWidget = widgets.value.find(w => w.id === widgetId);
  
  // 使用最新数据创建窗口
  if (enabled) {
    await createWidgetWindow(updatedWidget);
  }
}
```

**修改文件：** `src/stores/widgetStore.ts` - 修改 `toggleWidget()` 函数
