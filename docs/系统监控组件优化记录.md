# 系统监控组件优化记录

## 📋 更新日志

### v0.1.3 - 2025-11-02

#### 移除的功能

##### 1. CPU 温度监控
**原因：**
- CPU 温度获取需要特殊的硬件访问权限
- `sysinfo` 库在 Windows 上不支持温度读取
- 需要额外的第三方库或驱动程序支持
- 实现复杂度高，且不同硬件支持度不一

**移除内容：**
- ✅ 前端显示界面（SystemWidget.vue）
- ✅ 变量定义 `cpuTemp`
- ✅ 相关文档说明

##### 2. 磁盘 I/O 速度监控
**原因：**
- 性能开销大（需要刷新所有进程信息）
- 数据准确性依赖于进程扫描频率
- 对系统资源消耗较高
- 用户需求优先级较低

**移除内容：**
- ✅ Rust 后端 `DiskIOStats` 结构
- ✅ `get_disk_io_speed()` 函数
- ✅ SystemInfo 接口中的 `disk_read_speed` 和 `disk_write_speed` 字段

## 💡 设计决策

### 为什么移除 CPU 温度？

1. **技术限制**
   - Windows 系统需要特殊权限访问硬件传感器
   - 不同主板/CPU 的温度获取方式不同
   - `sysinfo` 库不原生支持温度读取

2. **实现复杂度**
   - 需要集成额外的库（如 `wmi` 或 `sensors`）
   - 需要处理不同硬件的兼容性
   - 可能需要管理员权限运行

3. **用户价值**
   - 大多数用户不需要实时监控CPU温度
   - 专业用户有专门的温度监控软件
   - 移除后不影响核心功能

### 为什么移除磁盘 I/O 速度？

1. **性能考虑**
   - 每次更新需要遍历所有进程
   - 进程列表越多，开销越大
   - 频繁刷新影响整体性能

2. **数据准确性**
   - 基于进程的 I/O 统计不够精确
   - 系统级 I/O 需要更底层的API

3. **需求优先级**
   - CPU 和内存监控更重要
   - 磁盘空间监控已在磁盘组件中提供
   - I/O 速度对大多数用户不是必需信息

### 温度监控的可能方案

如果未来要重新添加温度监控，可以考虑：

1. **使用 WMI (Windows)**
   ```rust
   // 需要 wmi crate
   use wmi::{COMLibrary, WMIConnection};
   
   fn get_cpu_temp() -> Result<f32, Error> {
       let com_con = COMLibrary::new()?;
       let wmi_con = WMIConnection::new(com_con)?;
       // 查询 MSAcpi_ThermalZoneTemperature
       ...
   }
   ```

2. **使用专门的温度库**
   - 可能需要第三方驱动支持
   - 兼容性和维护成本较高

3. **作为可选功能**
   - 默认禁用
   - 用户可在设置中手动启用
   - 提供降级方案（不支持时显示"不可用"）
